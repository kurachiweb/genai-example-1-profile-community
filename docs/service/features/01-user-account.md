# 機能仕様 — User（アカウント管理）

エンティティ **User** のライフサイクル（登録・メール確認・ログイン・パスワード・アカウント編集・退会）に関するビジネスルールと受け入れ条件を定義する。

> 横断前提（認証・状態モデル・公開×メール確認の整合）は [00-common-rules.md](./00-common-rules.md) を参照。
> 対応エピック: EP-01。記法・ID 規約は [README.md](./README.md)。

## 1. エンティティ定義

1 ユーザー = 1 プロフィール（1:1）。アカウント作成時に、空の Profile が自動生成される（[02-profile.md](./02-profile.md)）。

| 属性 | 型 | 制約 | 備考 |
| --- | --- | --- | --- |
| id | 識別子 | 不変・非公開 | 内部主キー |
| email | 文字列 | 必須・一意（大文字小文字を区別しない）・最大 254 文字 | ログイン識別子 |
| passwordHash | 文字列 | 必須 | Argon2id（`BR-COMMON-003`） |
| status | 列挙 | `UNVERIFIED` / `ACTIVE` / `FROZEN` / `WITHDRAWN` | `00-common-rules` `COMMON-2` |
| emailVerifiedAt | 日時 | 任意 | 確認完了時刻 |
| createdAt / updatedAt | 日時 | 必須 | 監査用 |

## 2. ビジネスルール

### BR-ACCT-001 メールアドレス

- メールアドレスは一意（大文字小文字・前後空白を正規化して比較）とする。
- 形式は RFC 5322 に準拠する範囲で検証し、最大 254 文字。
- 既に登録済みのメールアドレスでの新規登録要求では、**アカウントの存在を第三者に漏らさない**ため、画面上は「確認メールを送信しました」と一律表示し、実際には登録済み宛に「既に登録済みである」旨の案内メールを送る。
  - 根拠: メール列挙攻撃の防止（`BR-COMMON-012`）。

### BR-ACCT-002 パスワードポリシー

| 項目 | 値 | 根拠 |
| --- | --- | --- |
| 最小長 | 10 文字 | NIST SP 800-63B は 8 文字以上を許容。共有サービスとして 10 を下限に。 |
| 最大長 | 128 文字 | パスフレーズ・パスワードマネージャを許容しつつ DoS を防ぐ。 |
| 構成要件 | 強制しない | 長さ優先（NIST 準拠）。記号必須等は課さない。 |
| 流出パスワード | 拒否 | よく使われる/流出済みパスワードのブロックリストに一致する場合は拒否。 |
| 表示名・メール一致 | 拒否 | メールアドレスのローカル部と同一など、推測容易な値は拒否。 |

### BR-ACCT-003 メール確認

- 登録直後の状態は `UNVERIFIED`。登録時に確認用リンク（トークン）をメール送信する。
- 確認トークンの有効期限は **24 時間**。期限切れ・使用済みトークンは無効。
- 確認リンクは**ワンタイム**。使用後は再利用不可。再送は可能（レート制限 `BR-COMMON-010`）。
- 確認完了で状態が `ACTIVE` に遷移し、`emailVerifiedAt` を記録する。
- `UNVERIFIED` の間も**ログイン・プロフィール編集は可能**だが、公開・公開 API・一覧/検索露出は不可（`BR-COMMON-007`）。

### BR-ACCT-004 ログイン・ログアウト

- 認証は `email` ＋ `password`。成功でセッション Cookie を発行（`BR-COMMON-001`）。
- 失敗時のメッセージは識別子を漏らさない統一文面（`BR-COMMON-012`）。
- ログイン試行はレート制限・連続失敗時のバックオフ対象（`BR-COMMON-010`）。連続失敗は監査ログに記録（`BR-COMMON-013`）。
- `WITHDRAWN` はログイン不可。`FROZEN` はログイン可だが操作が制限される（`BR-COMMON-005`）。

### BR-ACCT-005 パスワード変更（ログイン中）

- 現在のパスワードの再入力を必須とする。新パスワードは `BR-ACCT-002` を満たすこと。
- 変更成功時、**当該セッション以外のすべてのセッションを無効化**し、本人へ通知メールを送る。
  - 根拠: 乗っ取り対策。変更を本人が把握でき、他端末を締め出せる。

### BR-ACCT-006 パスワードリセット（未ログイン）

- メールアドレスを起点にリセット用トークンをメール送信する。トークン有効期限は **1 時間**・ワンタイム。
- 入力されたメールの**存在有無に関わらず同一の完了表示**を返す（列挙防止）。
- リセット完了時、すべてのセッションを無効化し、通知メールを送る。

### BR-ACCT-007 メールアドレスの変更

- ログイン中にメールアドレスを変更できる（US-0104）。
- 新メールアドレスへ確認リンクを送り、**確認完了をもって切り替え**を確定する。確認までは旧メールアドレスが有効。
- 変更要求時は現在のパスワード再入力を必須とする。旧・新の双方へ変更通知を送る。

### BR-ACCT-008 アカウント情報の編集

- 編集可能な情報: メールアドレス（`BR-ACCT-007`）、パスワード（`BR-ACCT-005`）、通知設定（メール通知の受信可否、[08-content-and-comms.md](./08-content-and-comms.md)）。
- プロフィール内容（氏名・職業・アイコン等）は別エンティティとして [02-profile.md](./02-profile.md) で扱う。

### BR-ACCT-009 退会（アカウント削除）

退会の方針は「**即時公開停止＋データ匿名化・監査ログ保持**」とする（復旧不可）。

- 退会操作にはパスワード再入力（または再認証）を必須とする。
- 退会と同時に次を行う:
  1. 状態を `WITHDRAWN` に遷移し、以後のログインを不可にする。
  2. 公開ページ・一覧/検索・公開 API からの露出を**即時停止**（`404` 相当）。
  3. ハンドル名を解放対象とする（再利用は `BR-SHARE` の予約保持期間後）。
  4. アイコン画像・SNS リンク・自己紹介など本人特定可能データを**削除または匿名化**する。
  5. API キーをすべて失効する。
- **監査ログ・不正対策に必要な最小限の記録は匿名化のうえ保持**する（`BR-COMMON-014`）。退会は監査ログに記録する。
- 退会は**公開 API からは実行不可**（画面操作のみ・再認証必須）。
  - 根拠: 不可逆操作の誤実行・乗っ取り時の悪用を防ぐ（[05-public-api.md](./05-public-api.md) `BR-API-010`）。

## 3. 受け入れ条件（Given/When/Then）

### 登録・メール確認

#### AC-ACCT-001 新規登録の成功（正常系）

- **関連ストーリー**: US-0101
- **Given**: 未登録のメールアドレスを持つ訪問者が登録画面にいる
- **When**: 有効なメールアドレスと `BR-ACCT-002` を満たすパスワードで登録する
- **Then**: アカウントが `UNVERIFIED` で作成され、空の Profile が生成され、確認メールが送信され、「確認メールを送信しました」と表示される

#### AC-ACCT-002 弱いパスワードの拒否（異常系）

- **関連ストーリー**: US-0101
- **Given**: 登録画面にいる
- **When**: 9 文字以下、または流出ブロックリストに一致するパスワードを入力して登録する
- **Then**: 登録は行われず、理由が分かるフィールド単位のエラーが表示される

#### AC-ACCT-003 登録済みメールでの再登録（異常系・列挙防止）

- **関連ストーリー**: US-0101
- **Given**: 既に登録済みのメールアドレスが存在する
- **When**: そのメールアドレスで新規登録を試みる
- **Then**: 画面表示は成功時と同一（「確認メールを送信しました」）で、当該宛には「既に登録済み」案内メールが送られる。新規アカウントは作成されない

#### AC-ACCT-004 メール確認の完了（正常系）

- **関連ストーリー**: US-0101
- **Given**: `UNVERIFIED` のユーザーが有効な確認リンクを受け取っている
- **When**: 24 時間以内に確認リンクを開く
- **Then**: 状態が `ACTIVE` に遷移し、以後はプロフィールが実効公開の対象となる（`BR-COMMON-007`）

#### AC-ACCT-005 期限切れ確認リンク（異常系）

- **関連ストーリー**: US-0101
- **Given**: 発行から 24 時間を超えた確認リンクを持つ
- **When**: その確認リンクを開く
- **Then**: 無効である旨が表示され、確認メールの再送導線が提示される

### ログイン・ログアウト

#### AC-ACCT-006 ログイン成功（正常系）

- **関連ストーリー**: US-0102
- **Given**: `ACTIVE` または `UNVERIFIED` のユーザーが存在する
- **When**: 正しいメールとパスワードでログインする
- **Then**: セッション Cookie が発行され、自分のダッシュボード/編集画面に遷移する

#### AC-ACCT-007 認証失敗（異常系・情報秘匿）

- **関連ストーリー**: US-0102
- **Given**: ログイン画面にいる
- **When**: 誤ったパスワード、または存在しないメールでログインを試みる
- **Then**: いずれの場合も「メールアドレスかパスワードが正しくありません」と統一表示され、どちらが誤りかは示されない

#### AC-ACCT-008 連続失敗のレート制限（境界値）

- **関連ストーリー**: US-0102
- **Given**: 同一識別子/IP からのログイン失敗が短時間に連続している
- **When**: しきい値（10 回 / 5 分）を超えて再試行する
- **Then**: 一時的に試行が制限され、再試行までの案内が表示され、失敗が監査ログに記録される

#### AC-ACCT-009 ログアウト（正常系）

- **関連ストーリー**: US-0102
- **Given**: ログイン中のユーザー
- **When**: ログアウトする
- **Then**: 当該セッションが即時無効化され、保護ページへアクセスするとログイン画面へ誘導される

### パスワード

#### AC-ACCT-010 パスワード変更で他セッション失効（正常系）

- **関連ストーリー**: US-0103
- **Given**: 複数端末でログイン中のユーザー
- **When**: 現在のパスワードを正しく入力し、新パスワードに変更する
- **Then**: 変更した端末以外のセッションが無効化され、本人へ通知メールが送られる

#### AC-ACCT-011 パスワードリセットの列挙防止（異常系）

- **関連ストーリー**: US-0103
- **Given**: パスワードリセット画面にいる
- **When**: 登録済み／未登録いずれのメールアドレスを入力する
- **Then**: どちらも同一の完了表示となり、登録済みの場合のみリセットメールが届く

#### AC-ACCT-012 リセットトークンの有効期限（境界値）

- **関連ストーリー**: US-0103
- **Given**: 発行から 1 時間を超えたリセットトークンを持つ
- **When**: そのトークンでパスワード再設定を試みる
- **Then**: 無効である旨が表示され、再発行導線が提示される

### アカウント編集

#### AC-ACCT-013 メールアドレス変更は確認完了で確定（正常系）

- **関連ストーリー**: US-0104
- **Given**: `ACTIVE` のユーザーがアカウント設定画面にいる
- **When**: 新しいメールアドレスとパスワードを入力して変更を申請する
- **Then**: 新アドレス宛に確認リンクが送られ、リンクを開くまでは旧アドレスが有効。確認完了で切り替わり、双方へ通知される

### 退会

#### AC-ACCT-014 退会で即時非公開・匿名化（正常系）

- **関連ストーリー**: US-0105
- **Given**: 公開プロフィールを持つ `ACTIVE` のユーザー
- **When**: パスワード再入力のうえ退会を確定する
- **Then**: 状態が `WITHDRAWN` になり、公開ページ・一覧/検索・公開 API が即時に `404` となり、本人特定可能データが匿名化され、API キーが失効し、ログイン不可になる

#### AC-ACCT-015 退会は公開 API から不可（異常系）

- **関連ストーリー**: US-0105 / US-0503
- **Given**: 有効な API キーを持つユーザー
- **When**: 公開 API でアカウント削除（退会）を試みる
- **Then**: 退会エンドポイントは公開 API に存在せず、該当要求は拒否される（画面操作・再認証が必要）
