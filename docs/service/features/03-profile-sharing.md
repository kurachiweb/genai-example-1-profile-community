# 機能仕様 — Profile（公開・共有）

エンティティ **Profile** の公開面（ハンドル名・固有 URL・公開/非公開の切り替え・公開ページ・OGP・QR）に関するビジネスルールと受け入れ条件を定義する。

> 横断前提（特に「公開×メール確認の整合」`BR-COMMON-006/007`）は [00-common-rules.md](./00-common-rules.md)。対応エピック: EP-03。
> プロフィール内容の編集は [02-profile.md](./02-profile.md)、閲覧者側の閲覧・検索は [04-profile-discovery.md](./04-profile-discovery.md)。

## 1. 概要

各ユーザーは一意の **ハンドル名** を持ち、固有 URL `https://<service-domain>/@{handle}` で公開ページにアクセスできる。
共有体験（渡すのが速い）の核であり、URL・OGP・QR を一級の体験として扱う（コンセプト「渡しやすさを設計に織り込む」）。

## 2. ビジネスルール

### BR-SHARE-001 ハンドル名の形式

| 項目 | 値 | 根拠 |
| --- | --- | --- |
| 文字種 | 半角英小文字・数字・ハイフン（`a-z0-9-`） | URL 安全・大文字小文字の混同を排除。 |
| 長さ | 3〜30 文字 | 短く覚えやすく、衝突を避けられる範囲。 |
| 先頭・末尾 | ハイフン不可 | 可読性・正規化のため。 |
| 連続ハイフン | 不可（`--` を許さない） | 紛らわしさ・なりすまし防止。 |
| 一意性 | 全ユーザーで一意（大文字小文字を区別しない） | 1 ハンドル = 1 公開ページ。 |
| 正規表現 | `^[a-z0-9](?:-?[a-z0-9])*$`（3〜30 文字） | 上記制約の形式表現。 |

### BR-SHARE-002 予約語

- 次のような語はハンドルとして予約し、登録不可とする: `admin` / `api` / `login` / `logout` / `signup` / `help` / `about` / `terms` / `privacy` / `settings` / `p` / `search` / `me` / `static` / `assets` / `null` / `undefined` 等。
- 予約語一覧の正本は実装の設定（環境変数または定数）で管理し、本書から参照する。
  - 根拠: ルーティング衝突・公式詐称の防止。

### BR-SHARE-003 ハンドルの初期割り当て

- アカウント作成時、Profile にはシステムが一時的なハンドル（例: `user-8f3a2b` 形式の自動採番）を割り当てる。利用者はこれを任意のハンドルへ変更できる。
  - 根拠: 「公開がデフォルト」（`BR-COMMON-006`）でも URL を即時に持てるようにする。実効公開はメール確認後（`BR-COMMON-007`）。

### BR-SHARE-004 ハンドルの変更と予約保持

| 項目 | 値 | 根拠 |
| --- | --- | --- |
| 変更可否 | 可能 | 「渡すのが速い」を支える、覚えやすいハンドルへ更新可能。 |
| 変更頻度上限 | 30 日あたり 3 回まで | 頻繁な変更による混乱・なりすまし循環を抑制。 |
| 旧ハンドルの再利用 | 解放まで **30 日間予約保持** | 直後の第三者取得によるなりすまし・誤誘導を防ぐ。 |
| リダイレクト | 変更後 **30 日間**、旧ハンドルの固有 URL から新ハンドルへ **301（恒久）転送**。30 日経過後は旧ハンドルで `404` | 既存リンク・QR・名刺の延命と、予約解放後の秘匿の両立。 |

- **転送先の解決**: 旧ハンドルの転送先は、予約元ユーザー（`reserved_handles.released_from_user_id`）の**現在のハンドル**を都度解決する。30 日以内に複数回変更した場合（`A → B → C`）でも、旧ハンドル `A`・`B` はいずれも現ハンドル `C` へ転送する。
- **秘匿との整合**: 転送先が**実効公開でない**（非公開・未確認・凍結・退会）場合は、転送せず旧ハンドルでも `404` 相当を返す（`BR-SHARE-006`・状態の秘匿）。**退会で手放した旧ハンドル**は予約保持のみ行い、転送はしない（[01-user-account.md](./01-user-account.md) `BR-ACCT-009`）。
- 301 はクライアントに恒久キャッシュされ得るため、30 日での失効に備え転送応答には短い `Cache-Control` を付す（実装上の注記）。
- ハンドル変更・解放は監査ログに記録する（`BR-COMMON-013`）。退会時のハンドルも 30 日予約保持後に解放する（[01-user-account.md](./01-user-account.md) `BR-ACCT-009`）。

### BR-SHARE-005 公開・非公開の切り替え

- visibility は `public` / `private` の 2 値。既定は `public`（`BR-COMMON-006`）。利用者はいつでも切り替えられる。
- **実効公開**は `effectivePublic()`（`BR-COMMON-007`）に従う。すなわち `private`、または所有者が `UNVERIFIED`/`FROZEN`/`WITHDRAWN` の場合、第三者には公開されない。
- 公開導線では、氏名など最小限の必須項目（`firstName`/`lastName`）の充足を促す。未充足でも公開は妨げないが、注意を表示する。
- 公開・非公開の切り替えは監査ログに記録する。

### BR-SHARE-006 公開ページの表示内容

- 公開ページは**ログイン不要**で閲覧でき、表示名・職業・アイコン・自己紹介・SNS リンクを「アイコン→名前→職業→リンク」の視線の流れで提示する（コンセプト「見るのが速い」）。
- 非公開・未確認・凍結・退会・存在しないハンドルへのアクセスは、**存在を秘匿するため一律 `404`（見つかりません）相当**を返す。
  - 根拠: ハンドル列挙・状態推測の防止（`BR-COMMON-012`）。
- 所有者本人がログイン状態で自分の非公開/未確認ページを開いた場合は、本人向けに状態（非公開・メール未確認）を提示する。

### BR-SHARE-007 OGP / メタ情報

- 公開ページは OGP / Twitter Card メタタグを出力する（US-0304）。
  - `og:title` = 表示名（＋職業）、`og:description` = 自己紹介の抜粋、`og:image` = アイコン（正規化済み）、`og:url` = 固有 URL、`og:type` = `profile`。
- 非公開・未確認・凍結のページは OGP に個人情報を含めず、汎用の説明のみを返す（露出抑制）。
  - 根拠: SNS 共有時の良い第一印象（コンセプト）と、非公開状態の秘匿の両立。

### BR-SHARE-008 QR コード

- 公開ページの固有 URL から QR コードを生成・表示・ダウンロードできる（US-0303。名刺・イベント用途）。
- QR は URL のみを符号化し、個人情報を直接埋め込まない。

### BR-SHARE-009 共有導線

- 固有 URL のワンタップコピー、主要 SNS への共有導線を提供する。
- 公開ページの正規 URL（canonical）は `https://<service-domain>/@{handle}` とする。

### BR-SHARE-010 検索エンジンの取り扱い

- 実効公開のページのみインデックス可能とする（`robots`/`sitemap`）。非公開・未確認・凍結・退会のページは `noindex` とし、サイトマップから除外する。
  - 根拠: 検索流入（SEO）と、非公開状態の秘匿の両立。

## 3. 受け入れ条件（Given/When/Then）

### ハンドル名

#### AC-SHARE-001 ハンドルの設定（正常系）

- **関連ストーリー**: US-0301
- **Given**: ログイン中の利用者が公開設定画面にいる
- **When**: 利用可能なハンドル `minato-satonaka` を設定する
- **Then**: 固有 URL `/@minato-satonaka` が割り当てられ、保存される

#### AC-SHARE-002 形式違反の拒否（異常系）

- **関連ストーリー**: US-0301
- **Given**: 公開設定画面にいる
- **When**: `Ab`（大文字・2 文字）や `-foo`（先頭ハイフン）や `a--b`（連続ハイフン）を入力する
- **Then**: 形式エラーが表示され、保存されない

#### AC-SHARE-003 重複ハンドルの拒否（異常系）

- **関連ストーリー**: US-0301
- **Given**: 既に使われているハンドルが存在する
- **When**: 同じハンドル（大文字小文字違いを含む）を設定しようとする
- **Then**: 「このハンドルは使用できません」と表示され、保存されない

#### AC-SHARE-004 予約語の拒否（異常系）

- **関連ストーリー**: US-0301
- **Given**: 公開設定画面にいる
- **When**: 予約語（例: `admin`, `api`）をハンドルに設定しようとする
- **Then**: 使用不可である旨が表示され、保存されない

#### AC-SHARE-005 変更頻度の上限（境界値）

- **関連ストーリー**: US-0301
- **Given**: 直近 30 日にハンドルを 3 回変更済みの利用者
- **When**: 4 回目の変更を試みる
- **Then**: 上限到達の案内が表示され、変更できない

#### AC-SHARE-006 旧ハンドルの予約保持（異常系）

- **関連ストーリー**: US-0301
- **Given**: あるユーザーがハンドルを変更し、旧ハンドルが解放前（30 日以内）である
- **When**: 別ユーザーがその旧ハンドルを取得しようとする
- **Then**: まだ取得できない旨が表示され、設定されない

### 公開・非公開

#### AC-SHARE-007 公開ページの一般閲覧（正常系）

- **関連ストーリー**: US-0301 / US-0401
- **Given**: メール確認済み（`ACTIVE`）で `public` の利用者
- **When**: 未ログインの閲覧者が `/@{handle}` を開く
- **Then**: ログイン不要で、アイコン・表示名・職業・自己紹介・SNS リンクが表示される

#### AC-SHARE-008 未確認ユーザーは第三者に非公開（重要・整合）

- **関連ストーリー**: US-0302 / US-0101
- **Given**: visibility が `public` だが所有者が `UNVERIFIED`
- **When**: 未ログインの第三者が `/@{handle}` を開く
- **Then**: `404` 相当が返り、個人情報は表示されない。本人がログインして開くと「メール未確認のため未公開」と案内される

#### AC-SHARE-009 非公開への切り替え（正常系）

- **関連ストーリー**: US-0302
- **Given**: 公開中（`ACTIVE`・`public`）の利用者
- **When**: visibility を `private` に切り替える
- **Then**: 以後、第三者の `/@{handle}` アクセスは `404` 相当となり、一覧・検索・公開 API からも除外され、切り替えが監査ログに記録される

#### AC-SHARE-010 凍結ユーザーの公開停止（整合）

- **関連ストーリー**: US-0302 / US-0703
- **Given**: 公開中だったユーザーが管理者により `FROZEN` になった
- **When**: 第三者が `/@{handle}` を開く
- **Then**: `404` 相当が返り、一覧・検索・公開 API からも除外される

### 共有（OGP / QR）

#### AC-SHARE-011 OGP プレビュー（正常系）

- **関連ストーリー**: US-0304
- **Given**: 実効公開のプロフィール
- **When**: 固有 URL を SNS に貼る（OGP クローラがアクセスする）
- **Then**: 表示名・職業・アイコンを含む整った OGP プレビューが返る

#### AC-SHARE-012 非公開ページの OGP 秘匿（異常系・整合）

- **関連ストーリー**: US-0304 / US-0302
- **Given**: 非公開または未確認のプロフィール
- **When**: OGP クローラが固有 URL にアクセスする
- **Then**: 個人情報を含まない汎用的なメタ情報のみが返る

#### AC-SHARE-013 QR コードの生成（正常系）

- **関連ストーリー**: US-0303
- **Given**: 公開設定画面にいる利用者
- **When**: QR コードを表示・ダウンロードする
- **Then**: 固有 URL を符号化した QR が得られ、読み取ると公開ページに到達する

#### AC-SHARE-014 URL のワンタップ共有（正常系）

- **関連ストーリー**: US-0303
- **Given**: 公開設定画面にいる利用者
- **When**: 「URL をコピー」を操作する
- **Then**: 固有 URL がクリップボードにコピーされ、各 SNS への共有導線が提示される

### 旧ハンドルのリダイレクト

#### AC-SHARE-015 旧ハンドルからの 301 転送（正常系）

- **関連ストーリー**: US-0301
- **Given**: 利用者がハンドルを `old-handle` から `new-handle` に変更し、変更から 30 日以内（変更後も実効公開）
- **When**: 閲覧者が旧 URL `/@old-handle` を開く
- **Then**: `/@new-handle` へ `301`（恒久）転送され、新しい公開ページが表示される

#### AC-SHARE-016 予約解放後の旧ハンドル（境界値）

- **関連ストーリー**: US-0301
- **Given**: ハンドル変更から 30 日が経過し、旧ハンドルの予約保持が解放された
- **When**: 閲覧者が旧 URL `/@old-handle` を開く
- **Then**: 転送は行われず `404` 相当が返る

#### AC-SHARE-017 転送先が実効公開でない旧ハンドル（異常系・整合）

- **関連ストーリー**: US-0301 / US-0302
- **Given**: ハンドル変更から 30 日以内だが、変更したユーザーが `private`・凍結・退会のいずれかで実効公開でない
- **When**: 第三者が旧 URL `/@old-handle` を開く
- **Then**: 転送せず `404` 相当が返り、状態が秘匿される
