# デザイン総論 — スタイルディレクションと原則

本サービスの **ビジュアル方向（スタイルディレクション）** と、判断に迷ったとき立ち返る **デザイン原則** を定義する。
個別のトークン・配置・部品は [01-foundations.md](./01-foundations.md) 以降で具体化する。

> 本書はコンセプト [02-concept.md](../overview/02-concept.md) の「3 つの速さ」「デザイン原則」「トーン & マナー」をビジュアル面へ翻訳したものである。挙動の制約は [features/](../features/) を正本とする。

## 1. スタイルディレクション宣言

本サービスのビジュアル方向は **「温かみのある Bento（ベント）」** とする。
[.claude/rules/ecc-web/design-quality.md](../../../.claude/rules/ecc-web/design-quality.md) が求める「特定のスタイル方向を 1 つ選ぶ」に従い、汎用的な "clean minimal" を既定にしない。

| 要素 | 方向 | 根拠（コンセプトとの対応） |
| --- | --- | --- |
| レイアウト原理 | **Bento レイアウト**（情報をタイル状に整理し、タイルのサイズ差で階層をつくる） | 名前・職業・リンクという独立した情報を「一目で」捉えられる（見るのが速い） |
| 雰囲気 | **温かく、軽く、整っている** | トーン & マナー「親しみやすく軽い／整っていて信頼できる」 |
| 主役 | **ユーザーの内容**（アイコン・名前・リンク） | デザイン原則「クリエイターを主役にする」 |
| テーマ | **ライト基調＋ダーク両対応** | 既定でダークにしない（[tailwind §5](../../GUIDES/coding/05-tailwind.md)）。両テーマを意図的に設計 |
| アクセント | **コーラル／サンセット系を差し色 1 系統** | 創造性・親しみを、面ではなく線・状態・強調で添える |

### なぜ Bento か

- プロフィールは「アイコン」「名前・職業」「自己紹介」「複数の SNS リンク」という、**性質の異なる独立した情報の集合**である。Bento はこれらを枠（タイル）で分節し、サイズの強弱で「まず名前、次にリンク」という読み順を視覚的に表現できる。
- タイルの大小・余白のリズムで階層をつくるため、すべてを均一なカードグリッドに並べる平板さ（design-quality の禁止パターン）に陥りにくい。
- 一覧・編集・管理コンソールまで、同じ「タイルを組む」発想で一貫させられる。

### Bento を採用しても崩さないこと

- **視線の流れは `アイコン → 名前 → 職業 → リンク` を維持する**（[BR-SHARE-006](../features/03-profile-sharing.md)）。タイルに分けても、サイズと配置でこの優先順を表現する（[02-layout.md](./02-layout.md)）。
- **DOM 順（読み上げ順）と視覚的優先順を一致させる**。グリッド配置のために意味的な順序を入れ替えない（[04-content-a11y.md](./04-content-a11y.md)）。

## 2. デザイン原則（このサービス固有）

判断に迷ったとき立ち返る原則。コンセプトの 6 原則を、ビジュアル判断の language に具体化する。

1. **手軽さ＝速さを最優先する。** 装飾や演出が「作る・渡す・見る」の速さを 1 ミリでも損なうなら採らない。迷ったら足さない。
2. **クリエイターを主役にする。** サービスの chrome（ヘッダ・装飾・ブランド色の面）は控えめにし、ユーザーのアイコン・名前・リンクへ視線を集める。アクセントは主役を食わない範囲で使う。
3. **デフォルトで完成して見える。** 空欄・未設定でも体裁が崩れない。既定アイコン・プレースホルダ・空状態まで設計対象に含める（[03-components.md](./03-components.md)）。
4. **名前に敬意を払う。** 複合姓・多言語・長短のばらつきを、切り詰めや崩れなく扱う。名前はタイポグラフィの主役として最優先で美しく組む（[04-content-a11y.md](./04-content-a11y.md)）。
5. **健全さと安心を見た目で支える。** 通報・凍結・モデレーションの導線は、威圧せず分かりやすく。非公開・未確認は状態を秘匿しつつ、本人には何をすべきか明確に示す。
6. **共有される瞬間を一級に扱う。** 固有 URL・OGP・QR は「渡すのが速い」の核。共有導線・OGP プレビュー・QR は後付けでなく中心的なパーツとして配置する。
7. **画面と公開 API は対等。** 画面で表現する情報設計（視線の流れ・必須項目）は、公開 API のレスポンス（[05-public-api.md](../features/05-public-api.md)）と矛盾させない。

## 3. アンチテンプレート方針（本サービスへの適用）

[design-quality.md](../../../.claude/rules/ecc-web/design-quality.md) の「禁止パターン」「必須の質」を継承し、本サービスでは特に次を守る。

### 避けること

- **均一なカードグリッド**を一覧や編集画面に敷き詰め、階層のない平板な面にすること。Bento のサイズ差・余白リズムで強弱をつける（[02-layout.md](./02-layout.md)）。
- すべてのタイル・ボタン・カードに**同一の角丸・影・余白**を当てるだけの単調さ。エレベーション（重なり・影）に意味の差をつける（[01-foundations.md](./01-foundations.md)）。
- コーラルのアクセントを**広い面に塗って主役を食う**こと。アクセントは線・状態・強調に限る。
- shadcn/ui や Tailwind の**素のテンプレート然とした見た目**をそのまま出すこと（[tailwind §7・§9](../../GUIDES/coding/05-tailwind.md)）。

### 満たすこと（design-quality「Required Qualities」から本サービスで重視する 5 点）

1. **スケールコントラストによる階層**（名前 ≫ 職業 ＞ 補助情報）。
2. **均一でない、意図されたリズム**の余白（Bento のタイル間ガター）。
3. **重なり・サーフェス・影による奥行き**（タイルのエレベーション差）。
4. **設計されたホバー/フォーカス/アクティブ状態**（[03-components.md](./03-components.md)）。
5. **意味的に使う色**（コーラルは「強調・選択・アクション」を表し、装飾の塗りに乱用しない）。

## 4. 実装・SSoT との関係

- 本書で定めるのは **意図と方向**である。色・サイズの**具体値（トークン）は [01-foundations.md](./01-foundations.md)** に、**実装（CSS 変数・Tailwind theme・shadcn/ui）は [coding/05-tailwind.md](../../GUIDES/coding/05-tailwind.md)** に置く。値の二重管理を避けるため、確定値は片方を正本として参照する。
- 文字数上限・状態・公開条件などの**挙動の確定値は [features/](../features/) を引用**し、本書では再定義しない（例: 名前各 50 文字・bio 500 文字・リンク 10 件は features/ が正本）。
