# サービス概要 — GenAI Profile Community

## 一言で

**自分の「名前・肩書き・リンク」を、固有 URL のページにまとめて、ワンタップで共有できるプロフィールカードサービス。**

クリエイターやフリーランスが、SNS のプロフィール欄・名刺・メール署名・DM など、あらゆる場所から「ここを見て」と一枚で渡せる自己紹介ページを、最短数分で用意できる。

## これは何か

GenAI Profile Community は、ユーザーが自分のプロフィール（アイコン画像・名前・職業・自己紹介・SNS リンク）を登録し、固有 URL の公開ページとして共有できる Web サービスである。

各ユーザーは、画面操作だけでなく公開 API を通じても自身のプロフィールを CRUD（作成・取得・更新・削除）できる。
公開 API には 1 分あたりのリクエスト数制限（Rate Limit）が設けられており、誰でも安心して使える健全な共有基盤を目指す。

クリエイター・フリーランスにとって、活動の入り口（ファーストインプレッション）は散らばりがちだ。
本サービスは「リンクを集約した手軽な共有ページ」という一点に価値を絞り、**作るのが速い・渡すのが速い・見るのが速い**プロフィールカードを提供する。

## 提供価値（核となる体験）

このサービスの核は **「手軽な共有ページ」** である。具体的には次の 3 つの速さを約束する。

1. **作るのが速い** — 会員登録後、必要項目を埋めるだけで公開ページが完成する。専門知識やデザイン作業は不要。
2. **渡すのが速い** — 固有 URL を 1 つ渡すだけ。SNS bio・名刺・署名・QR など、あらゆる導線に置ける。
3. **見るのが速い** — 受け取った相手は、ログイン不要で名前・肩書き・リンクを一目で把握できる。

> コンセプトの背景・思想は [02-concept.md](./02-concept.md)、想定ユーザーは [03-target-users.md](./03-target-users.md) を参照。

## 主な機能（利用者視点）

機能の網羅的な一覧は [README.md](../../../README.md) を、実装上の受け入れ条件は `docs/service/features/` を正本とする。ここでは利用者体験の観点で要約する。

### プロフィール管理

- アイコン画像のアップロード・変更（不適切画像の自動検出・ブロックにより健全性を担保）
- 氏名の登録（ファースト・ラストネーム。複合姓や海外名にも対応）
- 職業・職種の登録
- 自己紹介文の入力
- SNS アカウントリンクの登録（X、GitHub、LinkedIn など）
- プロフィールの公開・非公開切り替え

### アカウント管理

- メールアドレスとパスワードによる登録・ログイン
- パスワード変更・リセット
- アカウント情報の編集
- アカウント削除（退会）

### 共有・閲覧

- 固有 URL による自分のプロフィールページの公開
- 他ユーザーのプロフィール一覧・検索
- 名前・職業・自己紹介による絞り込み検索

### 公開 API

- RESTful API によるプロフィールの CRUD 操作
- API キーによる認証
- 1 分あたりのリクエスト数制限（Rate Limiting）

### 管理者機能（運営側）

- お知らせ・メール通知の配信、ヘルプ記事の編集
- ユーザー管理、不適切なアイコンのモデレーション、通報対応・凍結・解除リクエスト審査
- 管理者アカウント・権限管理、公開 API キーとレート制限の管理
- 利用統計・監査ログの閲覧、問い合わせ対応、規約・ポリシーの版管理

## 代表的な利用シーン

| シーン | 使い方 |
| --- | --- |
| SNS のプロフィール欄に 1 行 | 複数 SNS や作品リンクを 1 つの URL に集約し、bio に貼る |
| 名刺・名刺アプリの代わり | イベントや商談で「このページを見てください」と URL/QR を渡す |
| メール署名・DM の自己紹介 | 署名に固有 URL を入れ、初対面の相手に肩書きと連絡先を即共有 |
| 制作依頼の窓口 | クライアントが職業・実績リンクを確認し、連絡先 SNS に遷移 |
| 自作サイトへの埋め込み | 公開 API でプロフィールを取得し、ポートフォリオサイトに表示 |

## スコープ

### やること（このサービスが担うこと）

- リンクと基本プロフィールを集約した、手軽で共有しやすい公開ページの提供
- 画面操作と公開 API の両方からのプロフィール CRUD
- 健全な運営のためのモデレーション・通報・凍結の仕組み
- 複合姓・多言語に対応した柔軟な名前表現

### やらないこと（スコープ外）

- 作品・ポートフォリオそのものの本格的なホスティング（あくまでリンク集約に徹する）
- DM・チャット・フォロー/フォロワーなどの SNS 的な交流機能
- 決済・課金・マーケットプレイス機能
- 高度なページデザインのカスタマイズ（テーマ自由編集・独自 HTML 等）

> スコープの線引きは「手軽さ」を守るための意図的な判断である。理由は [02-concept.md](./02-concept.md) の「デザイン原則」を参照。
