# どのユーザーがこのサービスを必要とするか — ターゲットとペルソナ

> サービス概要は [01-overview.md](./01-overview.md)、思想は [02-concept.md](./02-concept.md) を参照。
> 本ドキュメントは「誰のためのサービスか」を、ターゲット像とペルソナで具体化する。

## ターゲット概要

主要ターゲットは **クリエイター・フリーランス** である。
肩書き・SNS・作品リンクを束ねた「リンク集約型のプロフィールカード」を、自己 PR の窓口として手軽に持ちたい層を中核に据える。

| 区分 | 対象 | 必要とする理由 |
| --- | --- | --- |
| プライマリ | フリーランス／個人事業のクリエイター（デザイナー、イラストレーター、ライター、エンジニア兼クリエイター 等） | 散らばった活動情報を 1 つの URL に集約し、初対面の相手へ即座に渡したい |
| プライマリ | 副業・兼業でクリエイティブ活動をする会社員 | 本業と切り分けた公開プロフィールを、手軽に・非公開も使い分けて持ちたい |
| セカンダリ | プロフィールを「見る」側（クライアント、採用担当、コラボ相手） | 相手の肩書き・実績リンク・連絡先を、ログイン不要で素早く把握したい |
| セカンダリ | 公開 API でプロフィールを扱う開発者 | 自作サイト/アプリに自分のプロフィールを取得・反映したい |

## なぜこの層なのか（前提となる課題）

クリエイター・フリーランスは、次のような共通の不便を抱えている。本サービスはこれを「手軽な共有ページ」で解く。

- **情報の散らばり**: X・Instagram・GitHub・ポートフォリオ・連絡先が別々で、「どこを見て」を毎回説明している。
- **作成・維持コスト**: 自前サイトは作るのも保つのも手間で、活動の本筋ではない。
- **渡しにくさ**: 名刺・DM・署名など、場面ごとに自己紹介をやり直している。
- **見せたくない時もある**: 状況に応じて公開・非公開を切り替えたい。

## ペルソナ

### ペルソナ 1：里中 みなと（フリーランスのイラストレーター）

- **属性**: 28 歳／フリーランス 3 年目／作品は X と Instagram に投稿
- **状況**: 仕事の依頼は DM 経由。プロフィール欄に貼れる URL が複数あり、毎回どれを見てほしいか説明している。
- **ニーズ**: アイコン・肩書き・各 SNS・連絡先を 1 つの URL にまとめ、bio に貼りたい。
- **本サービスでの体験**: 数分でプロフィールを作成し、固有 URL を各 SNS の bio に設定。依頼者は 1 ページで全リンクを把握できる。
- **刺さる価値**: 作るのが速い／渡すのが速い。

### ペルソナ 2：小田原 風香（副業クリエイターの会社員）

- **属性**: 31 歳／平日は会社員、週末はハンドメイド作家として活動
- **状況**: 本業と作家活動を分けたい。イベント時だけプロフィールを見せ、普段は控えめにしたい。
- **ニーズ**: 公開・非公開を切り替えられ、必要な時だけ URL を渡せる手軽さ。
- **本サービスでの体験**: 普段は非公開、イベント前に公開へ切り替え。名刺代わりに QR で URL を渡す。
- **刺さる価値**: 公開/非公開の切り替え／手軽さ。

### ペルソナ 3：佐藤 賢人（エンジニア兼クリエイター）

- **属性**: 26 歳／Web エンジニア／個人でポートフォリオサイトを運用
- **状況**: プロフィール情報を自作サイトと本サービスで二重管理したくない。
- **ニーズ**: 公開 API で自分のプロフィールを取得し、ポートフォリオサイトに自動反映したい。
- **本サービスでの体験**: API キーを発行し、公開 API でプロフィールを取得して自作サイトに埋め込む。更新は本サービス側で一元化。
- **刺さる価値**: 公開 API による可搬性／一元管理。

### 閲覧者ペルソナ：山田 涼（制作依頼を検討するクライアント）

- **属性**: 39 歳／事業会社の担当者／クリエイターに制作を依頼したい
- **状況**: 候補者の肩書き・実績・連絡先を、できるだけ早く確認したい。
- **ニーズ**: ログインや会員登録なしで、相手のプロフィールと SNS をすぐ見たい。検索で候補を探したい。
- **本サービスでの体験**: 共有された URL をログイン不要で開き、一目で把握。名前・職業で他の候補も検索する。
- **刺さる価値**: 見るのが速い／検索で探せる。

## アンチペルソナ（今回は主対象としない層）

「手軽さ」という核を守るため、以下の層は主たる設計対象から外す（[02-concept.md](./02-concept.md) のスコープ判断に基づく）。

- **本格的なポートフォリオ運用を求める層**: 作品ホスティングや高度なデザイン編集が主目的のユーザー。本サービスはリンク集約に徹する。
- **SNS 的な交流を求める層**: フォロー/フォロワー・DM・タイムラインでの交流を期待するユーザー。交流機能は提供しない。
- **EC・課金窓口を求める層**: 販売・決済・予約を主目的とするユーザー。決済機能は扱わない。

## ペルソナと価値・機能の対応

| ペルソナ | 主に刺さる価値 | 主に使う機能 |
| --- | --- | --- |
| 里中 みなと | 作る/渡すのが速い | プロフィール作成、固有 URL 共有、SNS リンク |
| 小田原 風香 | 公開/非公開の切り替え | 公開・非公開トグル、URL 共有 |
| 佐藤 賢人 | API による可搬性 | 公開 API、API キー |
| 山田 涼（閲覧者） | 見るのが速い／検索 | プロフィール閲覧、一覧・検索 |
