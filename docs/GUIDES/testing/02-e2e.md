# E2E テスト規約 — GenAI Profile Community

Playwright による E2E テストの規約・重要フロー・補助テスト（ビジュアル回帰/アクセシビリティ）・成果物・CI を定義する。
全体戦略は [00-overview.md](./00-overview.md)、単体/統合は [01-unit-integration.md](./01-unit-integration.md) を参照。

> **位置づけ**: 本ガイドは [ecc-web/testing.md](../../../.claude/rules/ecc-web/testing.md)・[ecc-common/testing.md](../../../.claude/rules/ecc-common/testing.md) を本サービスへ具体化したものである。
> テスト対象の受け入れ条件の正本は [docs/service/features/](../../service/features/)（`AC-*`）。
> **現状フェーズ**: `apps/` 配下は未実装で、本ガイドは実装に先行する規約である。

## 1. 方針

- E2E は **Playwright**（[CLAUDE.md](../../../CLAUDE.md)）。本サービスは正確性優先のため、E2E は**重要ユーザーフローに限定**する（網羅は単体/統合で担う、[00-overview.md](./00-overview.md) §3）。
- アプリの**ビルド成果物 / プレビュー**に対して実行し、本番に近い経路（`client`/`admin` の別ドメイン・別セッション）を再現する（`BR-COMMON-002`）。
- 外部 I/O は決定論化する（Rekognition 決定論的スタブ・SES→Mailpit・固定時刻/ULID、[00-overview.md](./00-overview.md) §5）。
- **決定的な待機**を用い、任意の固定タイムアウトに依存しない（[ecc-web/testing.md](../../../.claude/rules/ecc-web/testing.md)）。

## 2. 重要フロー（E2E 対象）

受け入れ条件（`AC-*`）から重要フローを選定する。フローと正本の対応:

| フロー | 概要 | 正本 |
| --- | --- | --- |
| 登録 → メール確認 → ログイン | 登録直後は `UNVERIFIED`、確認後 `ACTIVE`。Mailpit で確認リンクを取得 | [01-user-account.md](../../service/features/01-user-account.md)（US-0101/0102） |
| プロフィール編集 + アイコン | 氏名・職業・自己紹介・SNS リンク・アイコン（NSFW 判定はスタブ） | [02-profile.md](../../service/features/02-profile.md)（US-0201〜0205） |
| 公開/非公開 + 公開ページ | ハンドルの固有 URL・公開ゲート・OGP | [03-profile-sharing.md](../../service/features/03-profile-sharing.md)（US-0301/0302） |
| 閲覧・一覧・検索 | ログイン不要の閲覧、名前/職業/自己紹介の絞り込み | [04-profile-discovery.md](../../service/features/04-profile-discovery.md)（US-0401/0403/0404） |
| 公開 API キー発行 → 利用 → 制限 | キー発行（`read`/`full`）→ CRUD → `429`+`Retry-After` | [05-public-api.md](../../service/features/05-public-api.md)（US-0501〜0504） |
| 通報 → 凍結 → 404 | 通報、管理者による凍結、第三者には `404` 相当で秘匿 | [06-trust-and-safety.md](../../service/features/06-trust-and-safety.md) / [07-admin-console.md](../../service/features/07-admin-console.md) |

- 公開ゲートの検証は重要: 非公開・未確認・凍結・退会・不存在が第三者に**一律 `404` 相当**で秘匿されること（`BR-COMMON-007`）。

## 3. 構造・データ・分離

- **Page Object Model** で画面操作をカプセル化し、セレクタの散在を防ぐ。アクセシビリティロール/ラベル経由のセレクタを優先する。
- テストデータは各テストでセットアップ/クリーンアップし、独立に実行できるようにする。`client` と `admin` は**別セッション**として扱う（Cookie・ストレージを分離、`BR-COMMON-002`）。
- E2E の基本形（[ecc-web/testing.md](../../../.claude/rules/ecc-web/testing.md)）:

```ts
import { test, expect } from '@playwright/test';

test('公開プロフィールページが表示される', async ({ page }) => {
  await page.goto('/@example-handle');
  await expect(page.getByRole('heading', { level: 1 })).toBeVisible();
});
```

## 4. 補助テスト（重要画面に限定）

正確性優先のため、以下は**重要画面に絞って補助的**に実施する（[00-overview.md](./00-overview.md) §3）。

### 4.1 ビジュアル回帰

- Playwright 内蔵の `toHaveScreenshot` で主要画面のスクリーンショット比較を行う（外部サービス不要）。
- ブレークポイント **320 / 375 / 768 / 1024 / 1440 / 1920** を対象に、横溢れ（overflow）がないことを確認する（[ecc-web/testing.md](../../../.claude/rules/ecc-web/testing.md)）。
- 対象は公開プロフィールページ・プロフィール編集・一覧/検索など意味のある画面に限定する。ビジュアル回帰はカバレッジ目標を**置き換えない・補完する**。

### 4.2 アクセシビリティ

- **@axe-core/playwright** で主要ページの自動チェックを行う（[00-overview.md](./00-overview.md) §2）。
- **キーボード操作**（フォーカス順序・操作可能性）と **prefers-reduced-motion** の挙動、色コントラストを確認する（[ecc-web/testing.md](../../../.claude/rules/ecc-web/testing.md)）。

### 4.3 クロスブラウザ

- 既定は Chromium。重要フローは Firefox・WebKit でも確認する（スクロール・モーション・フォールバック、[ecc-web/testing.md](../../../.claude/rules/ecc-web/testing.md)）。

## 5. 成果物・CI

- **失敗時**にスクリーンショット・動画・トレースを保存し、原因調査に使う。
- フレーキーなテストは隔離（quarantine）し、安定化するまで必須ゲートから外す。固定タイムアウト由来の不安定さを作らない。
- E2E は CI でアプリのビルド/プレビューに対して実行する。実行位置・契機は [coding/02-lint-format-commit.md](../coding/02-lint-format-commit.md) §7・[infra/02-deployment.md](../infra/02-deployment.md) を参照。
- パフォーマンス（CWV）は **Lighthouse CI を CI ゲートに組み込まない**（採用しない、[00-overview.md](./00-overview.md) §2）。目標値（[ecc-web/performance.md](../../../.claude/rules/ecc-web/performance.md)）を設計指針とし、重要画面で随時手元計測する。
